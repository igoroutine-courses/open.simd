# Переносимый `simd`: поиск байта

Новый в Go 1.27 API без зависимости от архитектуры и фиксированной ширины вектора.
В исходном коде этого каталога нет импорта `simd/archsimd`.

```sh
GOEXPERIMENT=simd go run ./06_portable_simd/cmd/demo
GOEXPERIMENT=simd go test ./06_portable_simd/...
GODEBUG=simd=0 GOEXPERIMENT=simd go test -count=1 ./06_portable_simd/...
```

## Два способа обработки хвоста

### `SliceContains`: полные векторы + скалярный хвост

1. Создаёт `BroadcastUint8s(target)`; получает число байтов через `.Len()`.
2. Сравнивает каждый полный блок: `LoadUint8s(s).Equal(needle)`.
3. Объединяет маски совпадений через `Or`.
4. Проверяет скалярный хвост и сводит накопленную маску.

В переносимом `Mask8s` Go 1.27 нет `Any()` или `ToBits()`. Поэтому результат
сравнения сохраняется через `ToInt8s().Store`, а наличие ненулевого элемента
проверяется обычным циклом. Буфер имеет фактическую ширину, без скрытого предположения
«вектор всегда 16 байт».

**Компромисс:** все полные блоки сканируются даже при совпадении в первом байте.
Это осознанный учебный вариант накопления маски, не универсальная замена
`slices.Contains` и не обещание ускорения на любых данных.

### `SliceContainsPart`: частичная загрузка и частичная запись

`LoadUint8sPart` возвращает вектор и число реально загруженных элементов.
Неактивные позиции заполняются нулями. Поэтому при `target == 0` сравнение даёт
истину и в этих позициях. Мы записываем и проверяем **только `loaded` элементов**
через `StorePart(lanes[:loaded])`.

Этот вариант может завершиться после первого блока с совпадением, но требует
скалярного сведения маски для каждого блока. Он показывает безопасную обработку
частичных загрузок, а не оптимальный алгоритм поиска.

## Пример из доклада

19 байт, первые 18 равны 7, последний — 42:

- поиск 42 → `true`;
- поиск 99 → `false`;
- поиск 0 в `[]byte{1, 2, 3}` через частичную загрузку → `false`.

В тестах ширина берётся из API: проверяются все длины до `2*N+3`, все позиции
совпадения, разные значения байтов, невыравненные подслайсы, данные за границей
входа и отсутствие изменений исходного массива. Fuzz-тест сравнивает оба способа
с независимым эталоном `slices.Contains`.

```sh
GOEXPERIMENT=simd go test ./06_portable_simd -run='^$' -fuzz=FuzzContains -fuzztime=10s
GOEXPERIMENT=simd go test ./06_portable_simd -run='^$' -bench=BenchmarkContains -benchmem -count=5
```

Для просмотра API установленной версии:

```sh
GOEXPERIMENT=simd go doc simd.LoadUint8sPart
GOEXPERIMENT=simd go doc simd.Mask8s
```

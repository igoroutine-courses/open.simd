# Переносимое накопление и архитектурная редукция

```sh
GOEXPERIMENT=simd go run ./05_archsimd_for_another_arch
GOEXPERIMENT=simd go test ./05_archsimd_for_another_arch
GODEBUG=simd=0 GOEXPERIMENT=simd go run ./05_archsimd_for_another_arch
```

`main.go` суммирует полные блоки через `simd.Float32s`, получая ширину через `.Len()`.
После цикла горизонтальная сумма считается **один раз**, оставшиеся элементы —
скалярно. Результат примера 1…19 — **190**.

`sumArch` реализован отдельно для каждой архитектуры:

- arm64: `ToArch()` → `Float32x4`, два `ConcatAddPairs`.
- amd64: `Float32x8` — два `ConcatAddPairsGrouped`, затем сложение результатов
  двух 128-битных групп. Для `Float32x16` сначала складываются две половины.
- Остальные случаи, включая программную эмуляцию и 128-битный amd64-вектор:
  `Store` во временный слайс длиной `.Len()` и обычная сумма элементов.

Это пример спуска из переносимой абстракции к архитектурной там, где переносимый
API пока не предоставляет нужной операции. Общий файл не ссылается на SIMD-типы,
которых нет на текущей платформе.

Порядок сложения `float32` отличается от последовательного цикла. Битовое равенство
результатов не обещается: есть отдельные тесты точных целых значений, погрешности
для дробных чисел, NaN и бесконечностей. Фиксированный буфер на 64 элемента заменён
буфером фактической ширины вектора.
